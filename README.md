# 基于 STM32F103C8T6 的四轴机械臂

## 一、整体架构

**整体架构思路**

1. 上点后，按下 key 进入 host 接收模式
2. 上位机通过串口发送数据帧（包含坐标）
3. MCU 进入中断回调，将数据帧放入缓冲区内随后重新挂起中断
4. 进入协议层将其解析成相应的命令以及位姿数据
5. 先判断时候越界然后将这些数据进行逆解并判断是否有解能达
6. 将角度拷贝进运动层，进行线性插值
7. 由舵机驱动层来完成运动

> 在这个过程中，OLED 会以 50 ms 的周期进行更新位位姿及角度

### 1. APP_Init() 初始化

#### 1.1 环形缓冲区初始化

将 `read` 和 `write` 变量初始化

#### 1.2 协议解析的初始化

时间戳（检验心跳）初始归 0

#### 1.3 关节角初始化

- `Joint_Init()`：初始设置的脉冲 → 角度，同时给 `motion` 提供
- `Motion_Init()`：接收关节角，初始化初始角、当前角、目标角
- `Servo_Init()`：执行驱动舵机当初设定的角度

#### 1.4 串口初始化

打开中断接收，进入中断后进入回调函数

#### 1.5 初始 tick 时间

`HAL_GetTick()`

#### 1.6 按键

读取按键的初始状态

#### 1.7 命令层

得到关节角，计算初始位姿

#### 1.8 UI 初始化

OLED 初始化，清空状态绘制菜单页

### 2. APP_Run()

- **每 10 ms** 进行按键的扫描进入 `button_task`，如果 key2 短按进入 host 模式，将 `s_mode` 赋值为 host，按键只进行这个的赋值
- 在 menu 时跳过（`if == 0`）；（`if == 1`）在 host 每轮进行协议的解析 `Proto_Poll`，如果上位机发送过数据帧过来，就从已经写入数据帧的缓冲区里读取数据帧并开始查找包头，解析指令以及位姿数据，校验
- 之后接收刚刚读过来的指令 `cmd_task`，将进行 `switch` 选择，随后将位姿进行判断然后逆解 `IK_Solve()`，将角度存起来，然后进行运动层面的的设置，`Motion_MoveTo` 设置当前角度、目标角度、走多少步、走多久
- **每 20 ms** 进行运动驱动层的轮询 `Motion_Task()`，进行关节空间的线性插值设置，根据 `s = 3.0f * p * p - 2.0f * p * p * p` 算出插值的角度比例 s，每一步运动多少度
  - 接着 `apply_servo()` 进行舵机的驱动 —— 设置将角度转脉冲 `Joint_ThetaToUs`，再不断修改 `CCR`
- **每 50 ms** 进行 UI 轮询（OLED）先设置目前的 UI 界面各个数值，进入更新动作 `UI_Task()`，判断是需要整页刷新还是单页部分数据需要刷新 `draw_values()`
- **每 50 ms** 进行安全检测 `watchdog_task`，看上位机发送数据过程中通信有没有超时，或者运动完超过 500 ms 没有发送数据帧
  - 若 `now_ms - s_last_activity > UART_TIMEOUT_MS` 即为超时，启动自动急停.
